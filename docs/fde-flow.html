§ 1 FDE 란 무엇인가

§ 2 3-Actor Model

fde-harness 가 채택한 AI 시대 transpose. 원전 FDE 는 2-actor (Engineer + Operator) 였으나, AI 보조를 추가해 3-actor 로 확장. 셋의 책임 분리가 무너지면 FDE 가 아니라 SDD 가 된다.

👤
Echo
Operator · 도메인 전문가 · 코드 ❌

책임

  • 가치 정의
  • 우선순위 결정
  • 수동 검증
  • 도메인 권위

산출물

  • Spec 의 Why · Expected outcome (직접 인용)
  • Plan 응답 (승인 / 거절)
👨‍💻
Delta
Engineer · 도구 사용자 · 코드 ✓

책임

  • Echo 발화를 의역 없이 옮김
  • Spec 작성
  • 승인 게이트 통과
  • 구현·검증·Ratchet

산출물

  • Spec 본문 · 코드 · 테스트
  • AGENTS.md 규칙
🤖
AI
Assistant · Delta 의 보조 · Echo 와 직접 소통 ❌

가능한 것

  • Delta 의 반복 작업 흡수
  • Spec draft 초안
  • Plan 보고 초안
  • 코드 generation

금지

  • Echo 의 자리에 앉기
  • 가치 판단 · 우선순위
  • 도메인 권위적 결정

잘못된 등치 (헌장 § 1.2)

  • Echo = 개발자 → "도메인 전문가" 정의 무너짐. 그냥 SDD 가 됨
  • Delta = AI → 책임 주체 사라짐. Operator 의 말을 해석할 사람 부재
  • AI = Echo 의 대리 → AI 가 도메인 권위가 됨. FDE 의 가장 큰 위반

§ 3 5 Forcing Functions

FDE 실천을 SDD·Agile·DevOps 와 구분짓는 다섯 가지. fde-harness 는 이 5개에 대해 *어떤 형식이든 강제하는가* 로 평가된다. 각 F# 의 강도가 모드별로 다르다.

F1
Co-location
Engineer 가 Operator 옆에 있다. 인터뷰 ❌, 관찰 ✅.
얕은 진척
F2
Days-not-months
며칠 안 movable demo. perfectionism 거부.
진척 없음
F3
Operator Priority
PM 도 매니저도 아닌 Operator 가 우선순위 결정.
진척 없음
F4
Operator's Language
가치는 Operator 의 단위로. 분·결정·오류 건수. LOC ❌.
진척 없음
F5
Two-way Learning
Operator ↔ Engineer 양방향. 음+양 학습 영속화.
깊은 진척 ⭐

모드별 강도 매트릭스

같은 forcing function 도 모드에 따라 강도가 다르다. 스플릿은 F1·F2·F3 최대, 챔피언은 F4·F5 최대.

§ 5 가치 사이클 — 가설 · 검증 · 측정

FDE 의 진짜 사이클은 spec → impl → test 가 아니라 가설 → 구현 검증 → 가치 측정. Done means 통과는 구현 의 검증이지 가치 의 검증이 아니다.

flowchart TD Op["👤 Operator 발화"] --> H["🎯 가설 형성
Operator 단위로 정량화"] H --> S["📄 Spec 계약
What · Why · 가설 · Done means"] S --> P{"✋ Plan + 승인"} P -->|승인| I["⚙️ 구현"] I --> D{"✅ Done means 통과?"} D -->|구현 검증 통과| Dep["🚀 배포"] D -->|실패| Br["4가지 분기"] Br -.-> S Dep --> M["📊 Outcome 측정
가치 검증 ⭐"] M --> Next["다음 가설 우선순위 조정"] Next --> Op style Op fill:#f59e0b,color:#000,stroke:#f59e0b style M fill:#10b981,color:#000,stroke:#10b981 style P fill:#3b82f6,color:#fff,stroke:#3b82f6 style D fill:#3b82f6,color:#fff,stroke:#3b82f6 style Br fill:#ef4444,color:#fff,stroke:#ef4444

⚠️ 핵심 함정

가치 측정 없는 사이클은 닫혀 보이지만 실은 열려 있다. Done means 통과는 *구현* 의 검증. *가치* 의 검증은 배포 후 운영 환경에서만 일어난다. 다음 가설의 우선순위는 *이전 측정 결과* 의 함수여야 사이클이 진짜 연속된다.

§ 6 2-차원 등급 — 명명 정직성

fde-harness 는 자기 평가를 *2 차원* (F# 강도 × 모드 커버리지) 으로 한다. 등급 결과보다 *높은* 명명 사용 ❌ — 헌장의 가장 강한 binding 규칙.

모드 3/3
이름에서 FDE 제외

현재 fde-harness (v0.6.0): F# 강제 2 (F1 얕은 · F5 깊은) · 모드 커버리지 2.85/3 · 공통 조건 4/4 충족
→ FDE-inspired (multi-mode). FDE proper 까지 깊은 진척 2개 더 필요.
