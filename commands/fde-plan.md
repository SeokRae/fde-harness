# 구현 계획 수립 (코드 작성 금지)

다음 단계를 정확히 따라줘:

1. **다음 spec 찾기**
   - `specs/` 폴더의 모든 .md 파일 (단 `_template.md` 제외) 을 읽는다
   - `.harness/done.log` 에 ID가 없는 spec 중 가장 작은 번호를 선택한다
   - 인자가 주어진 경우 ($ARGUMENTS), 해당 spec ID를 우선한다

2. **spec 분석**
   - 선택된 spec 파일을 전체 읽는다
   - What / Why / Done means / Out of scope / Context 섹션을 파악한다

3. **계획 제시 (코드 작성 금지)**
   사용자에게 다음 형식으로 보고한다:

   ```
   📋 Spec: {ID} - {제목}

   **What (한 줄):** ...

   **Done means 체크리스트:** N개

   **수정/생성할 파일 (최대 5개):**
   - path/to/file1.py — 추가할 함수/엔드포인트
   - ...

   **테스트 케이스:**
   - test_xxx — ...
   - ...

   **예상 위험:**
   - ...

   **불명확한 점 (있다면):**
   - ...

   이대로 진행할까요? (진행 / 수정 / 거절)
   ```

4. **중요한 규칙**
   - 이 명령에서는 절대 실제 코드 파일을 수정하거나 생성하지 않는다
   - 사용자의 명시적 "진행" 응답을 받기 전까지 다음 단계로 넘어가지 않는다
   - "Out of scope"에 명시된 것은 계획에 포함하지 않는다
   - AGENTS.md의 "절대 하지 말 것" 섹션을 사전에 확인하고 위반 가능성을 사용자에게 미리 경고한다
