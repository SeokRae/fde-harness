# Spec ID: 010 — 스킬 리팩토링: 딥다이브 모드 정렬 + 트리거 키워드 분리

> spec 009 가 *헌장에 모드 차원* 을 추가한 후, 기존 두 스킬 (`fde-workflow`·`discovery-echo`) 의 본문이 *모든 모드를 함의* 하는 상태로 stale 됨. 본 spec 은 두 스킬을 *딥다이브 모드 전용으로 명시* 한다. 향후 스플릿·챔피언 모드 스킬 추가의 *전제* 작업.

## What (무엇을)

기존 두 스킬의 본문을 *모드 정렬* — 동작 변화 없는 문서 리팩토링.

1. **`skills/fde-workflow/SKILL.md` 갱신**
   - description 명확화 — *딥다이브 모드 워크플로우* 임을 명시
   - 본문 § 기본 원칙 — "FDE 방법론" → "FDE 딥다이브 모드"
   - 트리거 키워드 — "딥다이브" 키워드 추가, 다른 모드 키워드 (예: "스프린트", "champion") 와 충돌 방지
   - 헌장 § 1.4·§ 5.3 link 추가
   - 모드 외 사용 시 안내 (스플릿·챔피언 모드면 본 스킬 비활성)

2. **`skills/discovery-echo/SKILL.md` 갱신**
   - description 에 *딥다이브 모드 Discovery 단계 보조* 명시
   - 본문에 *"Discovery"* 단어의 *의미 분리* — 작업 모드 vs Discovery 단계
   - 트리거 키워드 — 모드 한정 키워드 추가
   - 헌장 link

3. **이름·디렉토리 변경 없음** — `skills/fde-workflow/` 와 `skills/discovery-echo/` 폴더명 유지. 큰 리팩토링 (디렉토리 이동) 은 별도 spec 후보.

## Why (왜) — 비즈니스 가치

PR #24 가 헌장에 3 모드를 박은 후 두 스킬은 *모드 미명시* 상태로 *모든 FDE* 를 함의함. 두 가지 문제:

1. **외부 사용자 혼란** — 스킬 본문이 "FDE 방법론" 이라고 함 → 스플릿·챔피언 모드 사용자가 *이 스킬이 자기 모드에도 적용된다* 고 잘못 가정 → 잘못된 사이클 진행
2. **다음 사이클 차단** — 스플릿·챔피언 모드 스킬 추가 시 트리거 키워드가 *기존 스킬의 키워드와 충돌* → 어느 스킬이 활성화될지 모호

본 spec 머지 후:
- 외부 사용자가 스킬 본문 한 줄에서 *모드* 식별 가능
- 다음 모드 스킬 (스플릿·챔피언) 추가가 *키워드 충돌 없이* 가능

## Expected outcome (정량)

- 본 PR 후 두 스킬의 description 첫 줄에 *모드* 단어 명시 — 측정: `grep "딥다이브" skills/*/SKILL.md` 가 양쪽 매치
- 본 PR 후 트리거 키워드에 모드 한정 추가 — 측정: 양쪽 본문에 "딥다이브" 키워드 명시
- 본 PR 후 헌장 link 명시 — 측정: 양쪽 본문에 `docs/fde-criteria.md` 링크 (앵커 §1.4·§5.3)

## Out of scope (안 하는 것)

- **스킬 이름·디렉토리 변경** — `fde-workflow → fde-deepdive-workflow` 등. 영향 범위 큼 (매니페스트·README·다른 ref 다 갱신 필요). 별도 spec 후보
- **"Discovery" 용어 충돌 완전 해결** — 헌장 § 7.3 의 미해결 항목. 본 spec 은 *스킬 본문 명시* 만, 헌장 자체 변경 ❌
- **스플릿 모드 스킬 신규** — 별도 spec
- **챔피언 모드 스킬 신규** — 별도 spec (graduation 외 monthly review·KPI 통합 등)
- **버전 bump** — 동작 변화 없는 문서 정리. version 0.3.0 유지
- **헌장 갱신** — 본 spec 은 *스킬 본문* 만, 헌장 변경 없음

## Open questions (불명확한 점)

- **이름 리네임 (`fde-workflow → fde-deepdive-workflow`)** 의 *효과 대비 비용* — 본 spec 의 Out of scope. 외부 사용자 혼란 시그널 감지 시 별도 spec 트리거.
- **"Discovery" 용어 충돌의 *근본 해결*** — 본 spec 은 스킬 본문에 *의미 분리 명시* 만. 헌장 § 7.3 의 미해결 큐는 여전히 그 큐에.

## Risks (위험 요소)

- **트리거 키워드 변경이 *기존 사용자 워크플로 깨뜨림*** — "FDE 워크플로우" 라고 평소 말하던 사용자가 본 스킬 자동 트리거 안 됨. 인지: 새 키워드 ("딥다이브") 와 기존 키워드 *둘 다 유지* — 점진 전환
- **헌장 link 가 stale 됨** — 헌장 § 번호가 미래에 바뀌면 본 스킬의 link 가 깨짐. 인지: *§ 번호 + 단원 제목* 둘 다 link 에 포함 (예: "§ 1.4 도구의 작동 모드")
- **외부 사용자가 *모드 명시* 가 *복잡* 하다고 느낌** — 인지: description 첫 줄은 *짧게* (한 줄), 본문에서 자세히

## Rollback plan (롤백 계획)

- 본 PR 의 두 SKILL.md 변경을 git revert
- 변경은 모두 *추가* 형태 (제거 없음) → revert 후 사용자 영향 없음
- 만약 트리거 키워드 변경으로 *기존 키워드 미작동* 신호가 들어오면 키워드만 즉시 추가 (rollback 보다 forward fix 권장)
